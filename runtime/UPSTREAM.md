## Build
`python scripts/compile_main.py 16` (lifted main → `build/obj`), then `python scripts/build_runtime.py`
→ `build/game.dll`, `build/game_native.exe`, `build/SDL3.dll`, `build/ssbu_glslang.dll`.
Dependencies (2026-10-16: found through an environment variable or `deps/<name>`, `scripts/toolchain.py`; no fixed paths): SDL3 3.4.18 VC, Vulkan-Headers vulkan-sdk-1.4.341.0, glslang 16.6.0 (+ MSVC for `ssbu_glslang.dll`), llvm-mingw 20260922 (default) or clang 9 + MSVC 14.51. One entry point: `python scripts/setup.py --dump <dump>`.

## Toolchain portability (2026-10-16, notes/toolchain-mingw.md)
Compiler-neutral changes that let the runtime build with llvm-mingw (clang 23, mingw-w64 UCRT) as well as clang 9 + MSVC;
clang 9's code for them is unchanged (checked: same TLS access sequence, all 44 host files compile).
- `clib.c`, `hitch.c`, `hostrt.c`, `libcxx.c`, `nnalbum.c`, `nncxxrt.c`, `nnlibc2.c`, `nnmovie_mf.c`, `nvn_gl.c`, `os_threads.c`,
  `sdklift_rt.c`, `nvn_front.h`, `nnnet_c4a.inc`: every `__declspec(thread)` is C11 `_Thread_local`. mingw-w64's headers turn
  `__declspec(x)` into `__attribute__((x))`, and clang ignores an unknown `thread` attribute (only a warning, hidden by `-w`):
  every thread-local of the runtime became one shared global and the game froze at frame ~22.
- `nnfs.c`: `#include <io.h>` for `_get_osfhandle` (was implicitly declared with an `int` result; an error from clang 16 on).
- `nvn_vk.c`: `vk_debug_cb` takes the parameter types of `PFN_vkDebugUtilsMessengerCallbackEXT` (clang >= 16 rejects the
  `VkFlags` version as an incompatible function pointer for the MSVC target).

mingw-only changes (2026-10-16, finding 96), under `#ifdef`, so the MSVC build's code is unchanged (checked: the
disassembly of all 44 host objects is identical before and after):
- `nvn_vk_wd.c` (freeze watchdog, included by `nvn_vk_draw.c`): `wd_walk`'s `__try` / `__except` only under `_MSC_VER`
  (clang has no SEH `__try` in C for the `*-windows-gnu` target); elsewhere `wd_stack_ok` checks with `VirtualQuery` that
  the stack pointer is in committed, readable memory with 512 bytes above it before each unwind step.
- `nnmovie_mf.c`: under `__MINGW32__` the SDK's prototype of `MFCreateMFByteStreamOnStream` (missing from mingw-w64's
  `mfidl.h`; `libmfplat.a` exports it), and `__atomic_fetch_or` instead of `InterlockedOr8` in the TEST-only
  `SSBU_MOVIE_TEST_RESYNC` (no `_InterlockedOr8` intrinsic in mingw).
- Build side (scripts/toolchain.py, `TOOLCHAIN=mingw`): `-D_WIN32_WINNT=0x0A00`, `-lopengl32 -lws2_32 -ladvapi32 -luuid`
  (what `#pragma comment(lib)` and MSVC's default `uuid.lib` give the MSVC build), mingw link options.

## Provenance of two inherited tables (2026-10-16, notes/release-audit.md section 5)
Both are marked `[Recomps#1]` in the code; the values the game sees are unchanged (checked value by value).
- `nncxxlib.c` `classic_table` (`std::ctype<char>::classic_table()`): upstream's 256 values copied from the SDK are replaced
  by a table built at compile time from public definitions: the character classes of the "C" locale as in libc++'s
  `builtin_table` (src/locale.cpp) and the class bits of libc++'s glibc `ctype_base` (glibc `_ISbit`, little endian).
  Same 256 values (compared with a test program).
- `nvn_stub.c` `g_devinfo` (`nvnDeviceGetInteger`): upstream's 0x62-entry table ("from an NVN device-info dump of a
  development unit", in the enum order of a non-public header) is replaced by values for the 35 pnames our main can pass
  (its call sites), each with its source: Tegra X1 facts published by deko3d (zlib) or the yuzu-lineage emulators
  (GPL-3.0), the Vulkan specification, or this runtime's own handling of the object. Other pnames now answer 0 (none
  was queried in any run). Values not sourced yet are marked OPEN in the comment and listed in the audit.
- 2026-10-17, `nvn_stub.c` `nvnDeviceGetInteger`: the answers now come first from the player's own sdk.
  `gen/make_gen.py` reads the fixed numbers NVN's code returns (the pname switch at sdk 0x2c0f30 and the getter it calls,
  each case a `mov w0/w8, #imm`) into `gen/nvn_devinfo.h` (81 of 96 pnames; generated, never published). `nvn_stub.c`
  keeps only what the sdk answers from its live device object (0x38 = 32 deko3d, 0x3b = 1 OPEN, 0x18 = 0 this runtime)
  and the publicly sourced values as documented fallback. Every pname the game asked for in any run gets the same answer
  as before (trace lines compared); 0x30 is now the sdk's 14 (upstream's table had 15; on a path no run reaches).
- 2026-10-17, `nvn_vk_draw.c`: the Vulkan disk cache (`..\cache\vk`: SPIR-V, stage records, `pipes.bin`, the driver's pipeline
  cache) was never written here: the code made `../cache/vk` but not its parent `../cache` (upstream's layout has it
  already), and CreateDirectory makes one level. The four places now make the parent first. Tested: a cold run wrote
  117 MB (1,773 SPIR-V files, 118 pipelines, 25 MB pipeline cache); warm runs read it back and made 0 pipelines at
  draw time; standard test run PASS. `shader_prepare` (Smash's preparation from data.arc) has no effect for Bayonetta 2:
  said so in `gfx_options.c`'s default text, and the launcher greys the option out.
- 2026-10-17, `nvn_vk_draw.c` / `gfx_options.c|h`: `aspect = keep | stretch` (graphics.ini; keep by default): the present keeps
  the picture's shape in a window of another shape, black bars around it (finding 105). `RS_MAX` 2.0 -> 3.0: for Bayonetta 2
  (1280x720) 3.0 is 4K, the pixel count upstream's 2.0 was measured for with Smash (1920x1080).
- 2026-10-17, `nnfs.c`: RomFS mods (the emulators' LayeredFS, finding 109): folders under `mods\` with a `romfs\`
  replace or add game files at the same rom: path; `config\mods.ini` [mods] / [prompts]; button prompt mods are layered
  only when chosen (`button_prompts`). `mod_family` guesses a prompt mod's kind from a word that starts with ds4, ds5,
  dualshock, dualsense, playstation, ps4, ps5 / xbox (or the word ps), so the DS4Prompts / XBOXPrompts folders of the
  GameBanana prompt mod 360121 need no [prompts] line.
